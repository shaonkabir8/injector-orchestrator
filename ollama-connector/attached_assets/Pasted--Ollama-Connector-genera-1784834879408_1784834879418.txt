# ☠️ Ollama Connector — Agentic Loop Engine

---

## 🚀 What It Does

- **🤖 Agentic Loop** – Runs an AI agent in a loop until all tests pass.
- **💾 Checkpoint & Resume** – Saves state every iteration. Resume from where it stopped.
- **🛡️ OOM Guard** – Monitors RAM usage. Switches models or saves checkpoint before crash.
- **📊 Real-Time Dashboard** – Live metrics: RAM, CPU, Tokens, Latency, Cost.
- **🔔 Notifications** – Desktop & Telegram alerts on completion or errors.
- **📦 Git Auto-Commit** – Commits every passing iteration automatically.
- **⚡ Parallel Models** – Runs multiple models simultaneously for consensus.
- **🌐 Web Dashboard** – Node.js server with real-time logs and charts.
- **🧩 Extensible** – Drop `.ext` files in `extensions/` folder.
- **🖥️ IDE Integration** – Works with Cursor, VSCode, and any OpenAI-compatible IDE.

create_file "src/core/connector.sh" '#!/usr/bin/env bash
#===============================================================

connector.sh – Core Connector Logic

#===============================================================

check_ollama() {
log STEP "Checking Ollama..."
if ! command -v ollama &> /dev/null; then
log WARN "Ollama not found. Installing..."
curl -fsSL https://ollama.com/install.sh | sh > /dev/null 2>&1 &
spinner $! "📦 Installing Ollama"
if ! command -v ollama &> /dev/null; then
log ERROR "Ollama installation failed."
return 1
fi
fi
if ! curl -s http://localhost:11434/api/tags > /dev/null 2>&1; then
log WARN "Ollama not running. Starting..."
ollama serve > /dev/null 2>&1 &
sleep 3
if ! curl -s http://localhost:11434/api/tags > /dev/null 2>&1; then
log ERROR "Ollama failed to start."
return 1
fi
fi
log SUCCESS "Ollama is running."
return 0
}

configure_cursor() {
log STEP "Configuring Cursor..."
local settings="$HOME/.config/Cursor/User/settings.json"
    mkdir -p "$(dirname "$settings")"
    if [ -f "$settings" ]; then
cp "$settings" "$settings.bak_$(date +%Y%m%d_%H%M%S)"
    fi
    if command -v jq &> /dev/null; then
        if [ ! -f "$settings" ]; then echo '{}' > "$settings"; fi
        jq '"'"'.customModels = [
            {"name":"Ollama Qwen2.5","provider":"openai","baseUrl":"http://localhost:11434/v1","apiKey":"ollama","model":"qwen2.5:7b"},
            {"name":"Ollama DeepSeek R1","provider":"openai","baseUrl":"http://localhost:11434/v1","apiKey":"ollama","model":"deepseek-r1:8b"}
        ] + (.customModels // [])'"'"' "$settings" > "$settings.tmp"
        mv "$settings.tmp" "$settings"
        log SUCCESS "Cursor configured with jq."
    else
        log WARN "jq not found. Creating minimal config."
        cat > "$settings" << 'EOF'
{"customModels":[{"name":"Ollama Qwen2.5","provider":"openai","baseUrl":"http://localhost:11434/v1","apiKey":"ollama","model":"qwen2.5:7b"}]}
EOF
log SUCCESS "Cursor configured (fallback)."
fi
return 0
}'

local tests="$3"
local messages="$4"
local cp_dir="$CHECKPOINT_DIR/iter_$(printf "%03d" "$iteration")"
    mkdir -p "$cp_dir"
echo "$code" > "$cp_dir/code.py"
echo "$tests" > "$cp_dir/test.py"
echo "$messages" > "$cp_dir/messages.json"
echo "$iteration" > "$cp_dir/iteration.txt"
echo "$(date -Iseconds)" > "$cp_dir/timestamp.txt"
log CHECK "Checkpoint saved: iteration $iteration"
}

load_checkpoint() {
local latest=$(find "$CHECKPOINT_DIR" -maxdepth 1 -type d -name "iter_*" 2>/dev/null | sort -r | head -1)
if [ -z "$latest" ]; then
        log WARN "No checkpoint found."
        return 1
    fi
    local iteration=$(cat "$latest/iteration.txt" 2>/dev/null || echo "0")
    local code=$(cat "$latest/code.py" 2>/dev/null || echo "")
    local tests=$(cat "$latest/test.py" 2>/dev/null || echo "")
    local messages=$(cat "$latest/messages.json" 2>/dev/null || echo "[]")
    echo "$iteration|$code|$tests|$messages"
return 0
}'

#===============================================================

metrics.sh – Metrics Collection & Predictive Analysis

#===============================================================

predictive_analysis() {
local history=("$@")
    local count=${#history[@]}
if [ "$count" -lt 3 ]; then
        log METRIC "Insufficient data for prediction."
        return 0
    fi
    local total=0
    for ((i=0; i<count; i++)); do
        total=$((total + history[i]))
done
local avg=$((total / count))
    local remaining=$((MAX_ITERATIONS - iteration))
local predicted=$((avg * remaining))
    local cost=$((predicted * 2 / 1000000))
log METRIC "Prediction: $predicted tokens (~$${cost} USD) for next $remaining iterations"
}

collect_metrics() {
local json=$(cat <<EOF
{
  "timestamp": "$(date -Iseconds)",
"iteration": "${iteration:-0}",
  "total_tokens": "${total_tokens:-0}",
"ram_percent": "$(free -m | awk '"'"'/^Mem:/{print $3*100/$2}'"'"')",
  "cpu_load": "$(uptime | awk -F'"'"'load average:'"'"' '"'"'{print $2}'"'"' | cut -d, -f1 | xargs)"
}
EOF
)
    echo "$json" >> "$METRICS_FILE"
log METRIC "Metrics collected."
}'

        const eventSource = new EventSource("/events");
        eventSource.onmessage = function(e) {

            }
            if (data.type === "log") {

            }
        };

        `);
    } else if (req.url === "/events") {

            "Cache-Control": "no-cache",
            "Connection": "keep-alive"
        });
        clients.push(res);

let lastLogSize = 0;
setInterval(() => {
try {
const stats = fs.statSync(LOG_FILE);
if (stats.size > lastLogSize) {

const lines = data.split("\n").filter(l => l.trim());
const newLine = lines[lines.length - 1];

else if (newLine.includes("STEP")) className = "step";
else if (newLine.includes("CHECK")) className = "check";

clients.forEach(client => client.write(`data: ${payload}\n\n`));
}
lastLogSize = stats.size;
}
} catch(e) {}
}, 500);

server.listen(PORT, () => {
console.log("🌐 Dashboard: http://localhost:" + PORT);
console.log("📡 Press Ctrl+C to stop");
});'

Overview

Ollama Connector is a modular Bash-based tool with pluggable extensions and a web dashboard.

Components

1. Core Engine (src/core/)

· connector.sh – Ollama & Cursor setup
· loop_engine.sh – Main agentic loop
· checkpoint.sh – Save/Resume state
· oom_guard.sh – Memory monitoring
· notifications.sh – Desktop/Telegram alerts
· git_auto.sh – Auto-commit
· metrics.sh – Metrics collection

2. Executables (src/bin/)

· setup_cursor_ollama.sh – Complete setup
· test_connector.sh – Test suite

3. Web Dashboard (src/web/)

· server.js – Node.js SSE server
· Real-time metrics and logs

4. Configuration (config/)

· settings.conf – User settings
· telegram.conf.example – Telegram bot config

5. Extensions (extensions/)

· Drop-in .ext files loaded at startup

Data Flow

1. User runs ollama_connector.sh
2. Config loaded from settings.conf
3. Core modules sourced
4. Main menu displayed
5. User selects action
6. Agentic loop runs with:
   · Checkpoint every iteration
   · OOM guard monitoring
   · Auto-commit on pass
   · Notifications on events
7. Metrics saved to metrics.json
8. Web dashboard serves real-time data

Extension System

Extensions are sourced in alphabetical order. Each extension should be a valid Bash script.'
